# NyaSmsForward Client（Windows + Android）开发计划

> 状态：**M0 脚手架已完成**，下一步 M2（配对、SSE、通知、会话浏览）。
> 本仓库独立于 `nyasmsforward-server` 和 `nyasmsforward-client-node`，只通过服务端仓库的 `docs/协议.md` 对接（配对 `pair/claim`、`messages`、`conversations`、`events` SSE、`outbound`）。
> 交互原型见服务端仓库 `docs/prototype.html` 的「桌面客户端」和「手机客户端」两页。

## 1. 定位

Web 平台的常驻客户端，不用打开网页也能看短信、收提醒、复制验证码、**回复**和**新发**短信。

- **Android 版**：装在你平时用的**主力手机**上（和放 SIM 卡的接收端手机 client-node 不是同一个 App，包名 `app.nya.smsforward.client`）。这是最方便的形态——新验证码直接出现在通知里，点一下复制，或在通知里直接回复。
- **Windows 版**：托盘常驻，新验证码弹浮窗，主窗口里回复 / 新发。
- 后续按需追加 macOS / Linux（Flutter 桌面成本低）；iOS 不计划（后台常驻连接受系统限制）。

## 2. 选型：Flutter（Windows + Android 一套代码）

> 这里改了之前的方案：最初按“只有桌面端”选了 Tauri v2，加入 Android 之后重新评估，改用 Flutter。

| 考虑点 | Flutter | Tauri v2 |
|---|---|---|
| Windows + Android 一套代码 | ✅ 成熟 | ⚠️ Android 支持较新，插件生态薄 |
| Android 通知（操作按钮、通知内输入回复）、前台服务、Keystore | ✅ 有现成插件，必要时写少量 Kotlin | ⚠️ 基本要自己写原生插件 |
| Windows 托盘 / 窗口控制 | ✅ `tray_manager` / `window_manager` | ✅ 内置 |
| 你已有的经验与流水线 | ✅ **NyaMail 客户端**：同样的 Windows + Android、托盘、`flutter_local_notifications`、`mobile_scanner`（扫码）、`flutter_secure_storage`、`local_auth`、Android keystore 签名、Windows zip 打包、`build-release.ps1` | ✅ NyaMarkdownor（仅桌面） |

结论：Android 版的核心体验（后台连接 + 通知里回复）是这个客户端最重要的部分，Flutter + 少量 Kotlin 更稳，并且可以直接复用 NyaMail 的工程结构、依赖和 CI。

Flutter 版本在 CI 里固定（`FLUTTER_VERSION`），沿用 NyaMail 的做法。

## 3.1 连接平台：配对、登录与长期有效

**只需要连接一次**，之后重启设备、断网、服务器重启、换域名都不需要重新登录。

**首次连接（配对页，两种方式）**

| 方式 | 流程 | 适合 |
|---|---|---|
| 配对码 | 服务器地址 + 6 位配对码（Web「设备与客户端」里生成，10 分钟一次性），Android 可扫码（`nyasmsforward://pair?server=…&code=…`）→ `pair/claim`（`kind=client`，带 `platform`） | Android 主力机（扫码最快） |
| 账号登录 | 服务器地址 + 管理员密码（已启用 TOTP 时再填动态验证码）→ `login-device` | Windows（不用先去 Web 生成配对码） |

- 密码**只用于这一次换令牌，不保存**；之后一直使用长期设备令牌。
- 拿到的 `scopes`（查看 / 回复 / 新发）决定界面里能用哪些功能：没有 `reply` 就不显示回复框，没有 `send` 就不显示“新短信”，并给出说明而不是报错。
- 地址校验：必须 `https://`；只有 `localhost` / 局域网地址允许 `http://`，并提示风险。可填设备名称（默认 “Windows 客户端 / Android 客户端”）。
- 令牌存系统安全存储：Android Keystore（`flutter_secure_storage`）/ Windows 凭据管理器，不写明文配置。

**日常运行**

- 判定“需要重新配对”必须严格（协议 §2.2）：只有 `401` + JSON `token_revoked / token_invalid / token_expired` 才回到配对页；网络错误、超时、`429`、`5xx`、裸 401（反代拦截）、`403` / `404` 一律**保留令牌**，指数退避重连（1s 起，上限 5 分钟，带抖动），无限重试。裸 401 时提示“服务器地址可能有误”。
- 回到配对页时：清除通知、保留设置（服务器地址、设备名称、快捷回复），只丢令牌；重新登录后自动恢复。
- 启动时先 `GET /me` 校验令牌与权限，并同步 `scopes`（管理员改了权限，客户端下次连接即生效）。

**连接设置页**（Android：会话列表右上角 ⚙；Windows：标题栏点服务器地址 / 托盘菜单）

- 服务器地址（可改；**改地址不需要重新配对**，保存后用 `/me` 验证并自动重连）。
- 设备名称、令牌状态（“长期有效 · 不会自动过期”）、当前权限（查看 / 回复 / 新发）、实时通道状态与最近连接时间。
- 「测试连接」、可选**证书指纹固定**（自签名证书用，默认关）、「断开并清除令牌」（二次确认）。

## 4. 共同功能

1. **配对 / 登录**：见 §3.1。
2. **实时接收**：维持 SSE（断线指数退避重连 + `Last-Event-ID` 补发）。令牌走 `Authorization` 头，不放 URL。收到 `read` 事件时同步未读数、撤销对应通知。
3. **会话**：按“设备 + 号码”归并，气泡区分：收到的 / 经平台发出的 / 手机上手动发出的（`origin`）。`notify=false` 的消息（手动发出、历史回补）不弹通知、不计未读。
4. **验证码**：识别并突出显示，一键复制；可选“自动复制新验证码”（Windows）。
5. **回复**：会话里内嵌回复框；收件人 / 设备 / SIM 取自原短信不可改；快捷回复（TD / Y / N / 1）；字母 ID 发件人禁用并说明原因；服务号显示“通常只识别特定指令”的提示；设备策略不足时显示原因（平台 / 手机端各是什么）。需要 `reply` 权限。
6. **新发**：选设备、SIM、收件人、内容；需要 `send` 权限，且目标设备的实际策略为“允许新发”，否则给出明确提示。
7. **发送状态**：排队 → 已下发 → 已发送 → 已送达 / 失败（含原因，如 `recipient_not_recent`、`policy_denied`、`scope_denied`），通过 SSE `outbound` 事件更新。
8. **安全**：可选“发送前需要系统认证”（生物识别 / Windows Hello，用 `local_auth`），默认关；令牌被盗时在 Web 设备页吊销，客户端收到 401 后清除本地令牌并回到配对页。
9. v1 **不做本地数据库**：启动时拉最近的会话，之后靠 SSE 增量；离线时只读展示内存里的内容。是否加本地缓存视使用体验再定。

## 5. Android 版

### 5.1 通知（核心体验）

| 渠道 | 用途 | 优先级 |
|---|---|---|
| 新验证码 | 识别到验证码的短信 | 高（悬浮通知），按钮：**复制验证码**、**回复** |
| 新短信 | 其他短信 | 默认，按钮：**回复**（字母 ID / 无权限时不显示） |
| 连接状态 | 前台服务常驻通知 | 最低，可折叠 |

- **通知内回复**：使用 Android 通知的直接回复（`RemoteInput`），在后台处理函数里读取令牌、调用 `POST /outbound`，回复结果以通知更新体现（已发送 / 失败原因）。
- **复制验证码**：通知按钮在后台写入剪贴板。Android 10+ 限制的是后台**读取**剪贴板，写入一般允许，但部分国产 ROM 会拦截——需要真机验证；被拦截时退化为点通知打开 App 内复制。
- 同一会话的通知合并；在任一端标记已读后撤销通知。

### 5.2 后台连接

- 用**前台服务**保持 SSE 连接（显示一条最低优先级常驻通知）。不使用 FCM（国产 ROM 不可靠，也不想依赖第三方推送）。
- 实现方案在 M2 开头用一个小 spike 定：
  - 方案 A：`flutter_foreground_task`（Dart 里跑 SSE 和通知逻辑，代码单份，省事）；
  - 方案 B：原生 Kotlin 前台服务 + 原生 SSE（更稳、更省电，代价是 Android 侧多写一份协议代码）。
  - 倾向先试 A，若在国产 ROM 上保活或耗电不达标再换 B。
- 引导用户开启自启动、忽略电池优化（同 client-node 的首次使用引导）；网络切换 / 开机后自动恢复连接（`RECEIVE_BOOT_COMPLETED`）。

### 5.3 权限

`POST_NOTIFICATIONS`、`FOREGROUND_SERVICE`（+ 类型）、`RECEIVE_BOOT_COMPLETED`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`、`CAMERA`（仅扫码配对）、`INTERNET`。**不需要**任何短信相关权限——短信由接收端 client-node 负责。

## 6. Windows 版

- **托盘**：未读角标、打开主窗口、暂停提醒、退出；关闭窗口最小化到托盘继续接收；单实例；可选开机自启。
- **提醒**：优先用系统 Toast（`flutter_local_notifications` 的 Windows 实现，需实测是否支持按钮 / 输入框）；新验证码另有“浮窗”方案——用 `window_manager` 控制一个无边框、置顶、右下角的小窗，大字验证码 + 「复制」按钮，7 秒自动消失，如果 Flutter 单窗口下体验不好则退回 Toast。
- **主窗口**：左会话列表、右会话详情 + 回复框，顶部“新短信”按钮；布局与 Web 管理台一致（样式沿用同一套设计 token）。

## 7. CI 与发布

两个工作流，固定 Actions 的 commit SHA 和 Flutter 版本（`FLUTTER_VERSION`）。

**`ci.yml`**（push / PR）

- `quality`（ubuntu）：`flutter pub get` → `dart run tool/check_version.dart`（`VERSION`、`pubspec.yaml`、构建号一致）→ `flutter analyze` → `flutter test`。
- `build-windows`（`windows-2022`）、`build-android`（ubuntu，debug APK）：仅 push 时跑，编译检查原生插件没被破坏。`windows-2022` 固定 Visual Studio 工具链，沿用 NyaMail 的做法。

**`release.yml`**（推送 `v*` 标签）

1. `verify`：`check_version.dart` 校验标签 = `v<VERSION>`，再跑 analyze 和 test。
2. `windows`（`windows-2022`）：`choco install nsis` → `scripts/build-release.ps1 -SkipAndroid`，产出**安装包**和便携 zip。
3. `android`（ubuntu）：用仓库 secrets 还原 keystore → `scripts/build-release.ps1 -SkipWindows -RequireSigned` → `apksigner verify`。没有 keystore 就直接失败，不会发布 debug 签名的包。
4. `publish`：汇总产物，发布到 GitHub Release。

产物（每个都带 `.sha256`）：

| 文件 | 说明 |
|---|---|
| `NyaSmsForward-Client_<版本>_x64-setup.exe` | Windows 安装包（NSIS，简体中文 / English） |
| `NyaSmsForward-Client_<版本>_windows_x64.zip` | Windows 便携版 |
| `NyaSmsForward-Client_<版本>.apk` | Android，arm64 + armv7，已签名 |

**Windows 安装包要点**（`installer/nyasmsforward-client.nsi`，思路参考 NyaTerminal 的 NSIS 方案，重写为不依赖 Wails）：

- 每台机器安装（需要管理员），仅 64 位 Windows 10+；默认装到 `Program Files` 下的 `NyaSmsForward` 目录，创建开始菜单和桌面快捷方式，并在“应用和功能”里登记卸载项。
- **原地升级**：复用上次的安装目录；检测到程序正在运行会提示先退出（含托盘图标）；升级前先清掉旧的 `data` 目录，避免残留旧资源。
- 安装结束页“立即运行”通过 `explorer.exe` 以**普通用户**权限启动，而不是继承安装器的管理员权限。
- 随包带上 `msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`（Flutter 运行时静态链接了 CRT，应用本身只依赖这三个），没装 VC++ 运行库的机器也能直接启动。
- 卸载**不删除**用户数据（设置、令牌在用户目录里）。
- **未做代码签名**：安装包和 exe 都没有签名，Windows SmartScreen 会提示“未知发布者”。需要购买代码签名证书后，在 `release.yml` 的 `windows` 任务里加一步签名，这不属于 M0。

Android 版本号：`versionName = VERSION`，`versionCode = major*1000000 + minor*1000 + patch`（与 client-node 相同），`pubspec.yaml` 里必须写成 `version: <VERSION>+<versionCode>`，由 `tool/check_version.dart` 强制。应用内更新检查沿用 GitHub Release 查询（如 NyaMail 的 `github_release_client`）。

## 8. 里程碑

- **M0（已完成）**：Flutter 工程骨架（Windows + Android）、配对页外壳、协议模型 / 地址校验 / 连接判定（与 client-node 共用同一批用例）、Windows 安装包 + 便携 zip、签名 APK、CI 与发布工作流。
- **M2 客户端查看**：配对页（配对码 / 账号登录 / 扫码）+ 连接设置（改地址、测试、断开）、SSE、会话浏览、验证码识别与复制；Windows 托盘 + 提醒；Android 前台服务 + 通知（复制验证码）。验收：主力手机锁屏后收到新验证码，通知里能一键复制；关闭 Windows 主窗口后仍能提醒；重启设备 / 服务器、断网后无需重新登录；Web 吊销令牌后回到配对页且设置保留。
- **M3 回复 + 新发**：会话内回复框、新发、快捷回复、发送状态；Android 通知内直接回复；scope / 策略不足时的提示。验收：在通知里输入回复 → 接收端手机用原卡发出 → 通知更新为“已送达”。
- **M4**：会话里区分“手机上发出 / 经平台发出”，`notify=false` 不弹通知。
- **M6**：正式发布：图标、首次使用引导，视需要加 Windows 代码签名。
